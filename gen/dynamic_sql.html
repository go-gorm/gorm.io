Two rules the generated code imposes:

  • DIY methods are generated on the per-model DO type, and in the default
    (context-aware) mode that type is reached through the model’s WithContext —
    query.User.WithContext(ctx).GetByID(10). Calling query.User.GetByID(10)
    directly does not compile unless you generate with the WithoutContext mode.
  • A gen.T result is the model struct itself; write *gen.T, []gen.T or
    []*gen.T in the interface signature to change the generated result shape
    ((result *model.User), (result []model.User), (result []*model.User)).

Generated-file layout

g.Execute() writes one <model>.gen.go per applied model into OutPath
(e.g. query/users.gen.go), plus one entry file (gen.go by default, name set
by Config.OutFile). The entry file defines Use(db) returning *Query, and —
when the WithDefaultQuery mode is enabled — the package-level Q and
per-model variables (query.User) wired by query.SetDefault(db).
